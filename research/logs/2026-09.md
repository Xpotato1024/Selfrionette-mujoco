# 2026年9月 研究・実装ログ

## 2026-09-07: R7-J-P2 physical limitのidentity不変条件を補正

- 日付: 2026-09-07
- 目的: P2のphysical limit resolutionが、placeholder identityをconcreteなjoint / motor / actuator relationとして扱わないことをP1のtyped limit boundaryまで一貫させる。
- 実施内容: `PhysicalLimit.name`をconstructor、deep validator、strict JSON decoderで共通のconcrete identity validatorへ接続した。validatorはoverridableなstr subclassを評価せずbuilt-in `str`だけを受け付ける。共有text validatorも同じ型境界をsource ID、revision、evidence referenceへ適用し、authoritative sourceのplaceholder検査を迂回できないようにした。envelope lookupとresolved-bounds lookupのqueryも同じvalidatorを通し、nested limitのbypassとdownstream resolutionがauthorityへ到達しないようにした。`unknown` / `unavailable`はconcreteなlimit nameとtyped status / reason / provenanceの組み合わせで保持する。
- 検証: placeholder variantsのdirect constructor、bypass後のvalidator / envelope、strict JSON decode、envelope / result / provider lookup、resolver downstreamをsoftware-only focused regressionで確認した。実機、physical numeric measurement、serial、OSC、robot outputは実行していない。
- 現在できるようになったこと: physical limit identity、envelope serialization / lookup、P2 resolution queryが同じplaceholder vocabularyを共有し、unknown evidenceをidentityの代用にせずfail-closedで扱える。
- 実験的価値: software projectionとphysical evidenceのidentity boundaryを再現可能に検証でき、未解決sourceをconcrete relationやauthoritative numeric boundへ昇格させる経路を狭めた。
- まだ言えないこと: authoritative physical numeric evidenceは0件のままである。mechanical stop、cable constraint、self-interference、environment clearance、dynamic feasibility、physical safety、実機動作は未検証である。
- 判断: existing bounds、unit、frame、provenance、seal、conversion、status semanticsは変更せず、`docs/experiment-notes/`は新しいexperiment conditionや観測結果を取得していないため更新しない。
- 未解決事項: P3以降のcollision / trajectory / output gateは別Issueのscopeであり、この修正では実装しない。
- 次の作業: stack全体のcanonical validationと独立reviewを実行する。
