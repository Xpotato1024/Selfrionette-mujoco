- 目的: free-space endpoint評価のEnvironment、Task、Evaluation条件をversioned production pluginとして固定し、#406がtest-only fixtureなしで6軸compositionを受け取れるようにする。

## 2026-08-20: R7-G software-only world/tool experiment runner

- 日付: 2026-08-20
- 目的: #495までに成立したproduction 6軸compositionを、analog fixtureからMuJoCo measured endpointとTask-owned transitionまでの有限・決定的なsoftware-only executionへ接続する。
- 実施内容: canonical world/tool manifest pairをproduction readiness / freezeへ通し、selected Environment、Input Source、Control Mapping、command route、Robot Bundleのtyped provider、MuJoCo、TaskExecutionBindingを結線するrunnerとthin module entry pointを追加した。manifest revisionとactual execution identityは独立入力として照合し、reset後のactual qpos / measured tool orientationをfrozen manifestへ検証する。providerはassembly時に一度だけ取得し、manifest cadenceのsimulation timeとtimeout由来のstep上限で実行する。
- 実測した範囲: canonical single-target fixtureを実MuJoCoで反復実行した。worldはTask-owned `success`へ57 step / 1.14 sで到達し、toolはTask-owned `failure`へ250 step / 5.00 sで到達した。両conditionでreset直後のmeasured initial endpoint handoffは`technical_invalid`にならず、同じrevision / manifest / conditionの再実行でclassification、step count、elapsed time、measured trajectory、terminal evidenceが一致した。
- failure semantics: stale source、source read failure、freeze後manifest変更、malformed fixture、invalid control-frame projection、qpos / command rejection、bounded stopをfail-closedで検証する。hold、stale、rejected、unavailable、invalidをnominalまたはsuccessへ変換しない。
- 現在できるようになったこと: hardwareやwall-clock pacingなしで、production 6軸selectionだけからworld/tool両conditionを実行し、TaskTransitionのclassification / canonical evidenceを改変せずin-memory resultとして取得できる。Evaluation Pluginはresolveするがmetricを実行しない。
- まだ言えないこと: `experiment-motion-log/v1` lifecycle、metric aggregation、CSV / JSON artifact、full deterministic E2E / completion audit、4-target pilot、participant study、metric妥当性、hardware safetyは未実装・未証明である。今回のcanonical fixture実行を研究pilot結果として保存・解釈しない。
- Experiment evidence impact: MuJoCo load / stepとrunner behaviorの確認は通常のautomated integration / software smokeであり、研究experiment data collectionではないため`docs/experiment-notes/`は更新しない。
- 次の作業: #407でtrial lifecycle recordingを接続し、#408でmeasured outcome / artifact、#409でdeterministic E2E / completion auditを行う。
